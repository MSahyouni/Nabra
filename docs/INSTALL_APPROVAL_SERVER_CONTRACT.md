# عقد سيرفر تصريح تثبيت نبرة

## الهدف

لا يبدأ معالج نبرة تثبيتاً جديداً قبل الحصول على موافقة صالحة من سيرفر مشرفي النظام. يعمل المسار وفق مبدأ **الفشل المغلق**: غياب العنوان، أو انقطاع الشبكة، أو رفض الرمز، أو انتهاء المهلة، أو نقص حقول الاستجابة يمنع التثبيت. لا تحتاج إزالة نسخة مثبتة إلى الاتصال بالسيرفر حتى تبقى استعادة الجهاز ممكنة.

## ضبط عنوان السيرفر

يُثبّت عنوان HTTPS داخل الحزمة وقت البناء ولا تعرض الواجهة خياراً لتغييره:

```powershell
dotnet build .\Nabrh.Installer\Nabrh.Installer.wixproj -c Release `
  -p:ReleaseBundle=true `
  -p:ApprovalServerUrl=https://admin.example.gov.sy/api/v1/install/authorize
```

العنوان الافتراضي `https://approval.invalid/api/v1/install/authorize` مخصص للتطوير ويرفض كل عمليات التثبيت. كما يفشل بناء `ReleaseBundle=true` إن لم يُستبدل بعنوان حقيقي.

## طلب الموافقة

يرسل المثبّت `POST` بصيغة JSON إلى العنوان المثبّت:

```json
{
  "product": "Nabrh",
  "version": "0.4.0.0",
  "action": "install",
  "approvalCode": "one-time-code",
  "deviceId": "SHA256-DEVICE-ID",
  "machineName": "PC-NAME",
  "userDomain": "DOMAIN",
  "userName": "user"
}
```

`deviceId` بصمة SHA-256 مشتقة محلياً من `MachineGuid` واسم الجهاز. رمز التصريح لا يُكتب في سجل المثبّت.

## استجابة الموافقة

الاستجابة الناجحة يجب أن تكون HTTP 2xx وأن تحتوي:

```json
{
  "approved": true,
  "message": "وافق مشرف النظام على التثبيت",
  "approvalToken": "opaque-or-signed-short-lived-token",
  "expiresAtUtc": "2026-08-21T12:30:00Z",
  "approvalId": "apr_01..."
}
```

يشترط المعالج أن يكون `approved=true`، والرمز غير فارغ، ووقت الانتهاء أبعد من الوقت الحالي بأكثر من 30 ثانية. أي استجابة أخرى تُرفض. المهلة الحالية للاتصال 20 ثانية.

## التثبيت الصامت

يمر مسار `/quiet` و`/passive` عبر الحاجز نفسه. يزوّد نظام النشر رمزاً مؤقتاً كمتغيّر Burn مخفي:

```powershell
.\Nabrh.Installer.exe /quiet NabrhApprovalCode=ONE_TIME_CODE
```

عند الرفض يعيد المثبّت رمز Windows رقم `5` (`ERROR_ACCESS_DENIED`). لا يُطلب الرمز عند `/uninstall`.

## ضوابط السيرفر المطلوبة للإنتاج

- إصدار رمز أحادي الاستخدام، قصير العمر، مربوطاً بالمستخدم والجهاز وإصدار نبرة.
- إبطال الرمز فور استخدامه، ومنع إعادة التشغيل المتكرر، ووضع حد لمعدل المحاولات.
- تسجيل المشرف صاحب الموافقة و`approvalId` والجهاز والوقت والنتيجة لأغراض التدقيق.
- عدم إرجاع سبب حساس للمستخدم، وعدم تسجيل رمز الطلب أو `approvalToken` في أي سجل عميل.
- تقييد TLS بشهادة موثوقة، ويفضل تثبيت مفتاح عام أو mTLS في البيئات عالية الحساسية.

## حدود الإنفاذ

الحاجز الأساسي موجود في الـBootstrapper، ويوجد شرط ثانٍ داخل MSI يرفض التثبيت الجديد إذا لم يمرر المعالج رمز الموافقة. هذا يمنع التجاوز العرضي بتشغيل MSI المستخرج، لكنه لا يمثل حاجزاً تشفيرياً أمام مسؤول محلي متمكن يستطيع تعديل الحزمة أو تمرير خصائص MSI يدوياً.

للإنفاذ المؤسسي الصارم يجب توقيع الحزمة وملفاتها بـAuthenticode، والسماح بتشغيل ناشر نبرة فقط عبر WDAC أو AppLocker، وإرجاع توكن موقّع قصير العمر يتحقق منه Custom Action موثوق ومربوط ببصمة الجهاز. تبقى سياسة نظام التشغيل هي الحد الأمني النهائي ضد مسؤول محلي كامل الصلاحيات.
