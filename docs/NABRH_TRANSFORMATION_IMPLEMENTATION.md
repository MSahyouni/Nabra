# تنفيذ تحويل المشروع إلى نَبْرَة

> أضيفت سياسة تصريح مركزي للتثبيت وواجهة كاملة للإزالة. تفاصيل البروتوكول وضبط الإصدار موثقة في [INSTALL_APPROVAL_SERVER_CONTRACT.md](INSTALL_APPROVAL_SERVER_CONTRACT.md).

## القرار المعماري

المسار المعتمد للإصدار الحالي هو تطبيق **Next.js + Tauri/Rust على Windows**. تبقى أجزاء Python القديمة مرجعاً للهجرة فقط، ولا تدخل في الحزمة المدعومة. يضاف مكوّن Windows صغير ومعزول مبني بـ .NET لتشغيل Word COM، بينما يبقى Ollama خدمة محلية يتصل بها التطبيق عبر `localhost:11434`.

هذا القرار يحافظ على قدرات التقاط الصوت والتفريغ الموجودة، ويقلل مخاطر إعادة كتابة المنتج كاملةً قبل تثبيت سلوك التلخيص والتصدير والتثبيت.

## البنية المنفّذة

```text
واجهة نَبْرَة (Next.js)
  ├─ أوامر Tauri
  │   ├─ التقاط الصوت / Whisper
  │   ├─ Ollama محلي: تلخيص منظّم متعدد المقاطع
  │   └─ Word export bridge
  ├─ Rust/Tauri
  │   └─ يشغّل Nabrh.WordExporter.exe بطلب JSON مؤقت
  └─ Nabrh.WordExporter (.NET self-contained)
      └─ Microsoft Word COM → DOCX عربي RTL

WiX Burn MBA
  ├─ فحص VC++ وWebView2
  ├─ فحص Word (غير حاجب، لكنه يوضح توفر التصدير)
  ├─ فحص Ollama (غير حاجب، لأنه يمكن تثبيته بعد التطبيق)
  └─ MSI: Nabrh.exe + sidecars + Word exporter
```

## الهوية البصرية

- الاسم الظاهر: `نَبْرَة`، والاسم اللاتيني التقني: `Nabrh`.
- المرجع: منظومة الهوية البصرية السورية في `https://syrian.zone/syid/` والنسخ المحلية داخل `Assets` و`Logos`.
- بناءً على تأكيد مالك المشروع، عناصر الهوية السورية المعتمدة هنا مفتوحة ولا تتطلب إجراء ترخيص منفصل.
- الخط الأساسي للعربية: Qomra Arabic بالأوزان Regular وMedium وBold؛ Light للنصوص الثانوية الكبيرة فقط.
- اللون الأساسي: أخضر داكن `#042623`، واللون المساند الذهبي `#B9A779`، مع خلفيات عاجية فاتحة ونص أسود عالي التباين.
- الاتجاه الافتراضي للشاشات العربية RTL، مع إبقاء الأرقام ومسارات الملفات وأسماء النماذج LTR.

## معالجة التلخيص عبر Ollama

المسار المحلي لا يولّد نصاً إنكليزياً ثم يترجمه إلى العربية. عند اختيار العربية أو اكتشافها كلغة مهيمنة، يُطلب من Ollama توليد العربية مباشرة. للاجتماعات الطويلة:

1. تقسيم التفريغ إلى مقاطع ضمن نافذة السياق.
2. طلب JSON مضبوط بمخطط ثابت لكل مقطع: نظرة عامة، نقاط أساسية، قرارات، مهام، مشاركون، وأسئلة مفتوحة.
3. رفض المقطع الفاشل بدل إخفائه وإخراج ملخص ناقص دون تنبيه.
4. دمج الملخصات الوسيطة بصياغة اللغة المطلوبة.
5. استخدام `think=false` و`keep_alive=10m` لتقليل زمن الاستجابة وعدم إدخال نص التفكير في الناتج.

معايير القبول: لا نجاح صامت عند سقوط مقطع؛ العربية تولّد مباشرة؛ JSON غير الصالح يعطي خطأ واضحاً؛ ويمكن إعادة المحاولة دون فقد التفريغ.

## التصدير إلى Word

يظهر زر Word بجوار أدوات الملخص. التدفق:

1. فحص تسجيل `Word.Application` ومسار `WINWORD.EXE`.
2. فتح نافذة حفظ أصلية وتحديد `.docx`.
3. تمرير عنوان الاجتماع وتاريخه والملخص والتفريغ إلى المصدر المستقل.
4. إنشاء مستند RTL بخط Qomra، عناوين وقوائم وتوقيتات التفريغ.
5. إغلاق المستند وWord وتحرير كائنات COM في `finally` حتى عند الفشل.

لا يوجد fallback صامت إلى ملف مزيف بامتداد DOCX. عند غياب Word يظل نَبْرَة قابلاً للتثبيت والاستخدام، وتظهر للمستخدم رسالة أن ميزة Word غير متاحة.

## المثبّت MBA

المثبّت الحالي WiX 7 Out-of-Process MBA وواجهة WPF UI 4.2.0 منشورة self-contained. التعديلات المعتمدة:

- لا حاجة إلى .NET Desktop Runtime على جهاز المستخدم.
- VC++ وWebView2 متطلبات تشغيل حقيقية.
- Word وOllama فحوص قدرة اختيارية وليسا سبباً لمنع تثبيت التطبيق.
- مساحة القرص الدنيا 8GB لاستيعاب النماذج والملفات المؤقتة.
- مسار التثبيت المختار في واجهة MBA يُمرر إلى خاصية `INSTALLFOLDER` في MSI.
- معرّفا الترقية للحزمة وMSI خاصان بنَبْرَة ولا يعيدان استخدام هوية مشروع MBA المصدر.
- المصدر المستقل `Nabrh.WordExporter.exe` يدخل MSI بجوار التطبيق.

## بوابات الإصدار

- بناء Word exporter وتشغيل `--capability` على Windows.
- اختبار COM فعلي ينشئ DOCX على جهاز فيه Word.
- فحص TypeScript وبناء Next.js بعد تثبيت اعتمادات frontend.
- `cargo check` واختبارات وحدة التلخيص في بيئة Visual Studio Developer Shell، ويفضل خارج مجلد متزامن أثناء بناء الاعتمادات الأصلية.
- بناء MSI ثم Bundle بملفات VC++ وWebView2 المحددة.
- اختبار تثبيت نظيف، إصلاح، ترقية، إزالة، وإلغاء تثبيت من ARP.
- اختبار Word موجود/غير موجود، Ollama موجود/غير موجود، ومسار تثبيت مخصص.

## ما لا يدخل في الإصدار الحالي

- إعادة كتابة التطبيق كاملاً إلى WPF.
- تنزيل Ollama أو النماذج خلسة أثناء التثبيت.
- إرسال التفريغ إلى خدمة سحابية افتراضياً.
- حذف مفاتيح أو مسارات `Meetily` القديمة المستخدمة حصراً لاكتشاف وترحيل بيانات مستخدم سابق.
